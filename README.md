### 3.5 협업 및 Push 규칙

`core/` 폴더는 전역으로 모든 작업자가 공유하므로, 아래 규칙을 따릅니다.

1. **`core/` 폴더 역할** — 모든 도메인이 공유하는 코드가 위치합니다. `config.py`는 `.env` 파일에서 API 키를 일괄 호출하고, `database.py`는 DB 연동(세션·연결)을 전담합니다.
2. **API 클라이언트 파일명 규칙** — 외부 API를 호출하는 파일은 `(api명)_client.py` 형식으로 작성합니다. (예: 한국투자증권 API → `kis_client.py`)
3. **함수 단위 주석 규칙** — 함수마다 어떤 데이터를 조회하는지 주석으로 명시합니다. (예: `# 국내 지수(코스피/코스닥) 현재가 조회`)
4. **`core/` 수정 시 push 규칙** — 기존 코드를 수정·삭제하는 경우 팀에 공지 후 `main`에 push, 추가만 하는 경우 공지 없이 push. 수정 후 push 전에는 반드시 `uv run fastapi dev main.py`로 서버를 한 번 띄워 정상 동작을 확인합니다.
5. **일반 작업 규칙** — 본인 브랜치에서 작업 후 push. 작업 시작 전 `git pull origin main`으로 최신 변경 사항을 받아옵니다.
6. **`.env` 관리** — 변동 사항은 담당자에게 개별 전달하며 저장소에는 커밋하지 않습니다.

**[구현 현황]** 초안에는 없던 절로, 실제 협업 과정에서 확정된 팀 규칙을 정리했습니다.

### 3.7 주요 설계 결정

- **도메인/데이터 선택 이유**: 상업적 재판매 목적 없이 크롤링 데이터를 그대로 노출하는 방식은 포트폴리오 프로젝트로 적합하지 않다고 판단해, "수집 데이터 + AI 인사이트"로 가치를 더할 수 있는 금융 시황 도메인으로 전환했습니다. 주식은 데이터 신뢰도와 팀의 도메인 이해도를 고려해 국내 상장사로 한정했고, 지표·뉴스는 "글로벌 맥락 속의 국내 시황"을 보여주기 위해 해외까지 포함했습니다.
- **DB 스키마 설계 이유**: 모든 테이블을 외래키 대신 "같은 날짜(date)"로 느슨하게 연결했습니다. 지표·뉴스·일정·섹터가 서로 다른 소스에서 비동기로 수집되기 때문에, 엄격한 FK 제약보다 date 매칭이 한 소스의 수집 실패가 다른 데이터 조회에 영향을 주지 않아 더 안전합니다. `DATABASE_URL` 하나만 바꾸면 SQLite → Supabase(PostgreSQL)로 전환되도록 설계했습니다.
- **LLM API 연동 방식**: 아직 팀에 LLM API가 지급되지 않아, 우선 규칙 기반(통계 z-score 이상치 탐지 + 감성 키워드 사전) 로직으로 인사이트를 구현했습니다. "데이터 → 문장" 변환을 별도 계층(`generator.py`/`report_generator.py`)으로 분리해, LLM 연동 시 그 부분만 교체하면 되는 구조입니다.
- **예외 처리 구성**: 모든 외부 수집기가 "실 API 우선 시도 → 실패 시 결정론적 샘플 데이터로 자동 폴백" 구조이며, 실패 시 예외 대신 로그로 원인을 기록하고 다음 단계로 진행합니다.
- **대시보드 지표 선정 이유**: 헤더 지표는 국내 투자자가 가장 먼저 보는 6개 지수·환율로 선정했습니다. 히트맵은 개별 종목 대신 대표 섹터 단위(6~9개, 가변)로 구성해 "지금 자금이 어디로 몰리는지" 큰 흐름을 먼저 이해시키는 것이 입문자의 학습 곡선에 자연스럽다고 판단했습니다.

**[구현 현황]** 초안에는 없던 절로, 실제 구현 과정에서 내린 설계 결정과 그 이유를 정리했습니다.
